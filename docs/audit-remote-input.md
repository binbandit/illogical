# Remote operation and terminal input parity audit

Audit date: 20 September 2026. Scope: R01–R09 and the input/protocol portion of T02 in [the feature inventory](../research/superlogical/FEATURES.md). This audit inspected the current Swift/Go/C implementation and ran the isolated checks recorded below. It did not connect to an external SSH host, use the user's Tailscale account, or operate the default or QA daemons. Runtime source was not changed.

**Full remote parity is not established.** The largest implementation gaps are real login/PAM sessions, integrated Tailscale node/service registration, and normal local CLI commands targeting a configured remote host. The existing QUIC authentication and persistent-process tests pass on loopback. They do not establish a complete Linux remote deployment or native remote workflow.

Status meanings: **verified** means the stated narrow behavior has direct test evidence; **partial** means a working or implemented subset exists with a known gap; **missing** means the defining behavior has no implementation; **unverified** means the code path exists but the required acceptance scenario has not been demonstrated. A passing transport test is not a passing UI, login, or interoperability test.

## Checks executed for this audit

All checks below passed on this Mac on 20 September 2026; the logged run began at approximately 19:47 AEST. Go tests create and clean private temporary service directories and sockets via `startTest`; the QUIC listeners bind loopback. The input fixtures create their own PTYs. No existing user's process or daemon was used.

```sh
mkdir -p .build/audit
set -o pipefail
PKG_CONFIG_PATH="$PWD/.build/ghostty/share/pkgconfig" \
  /opt/homebrew/bin/go -C service test -race ./internal/mux \
  -run 'Test(QUICMutualTLSAndPersistentReconnect|OSCWorkingDirectoryAndForegroundMetadata|BlockedInputDoesNotBlockWorkspace|TerminalRepliesSurviveAnInFlightPaste|ControlCInterruptsForegroundProcess)$' \
  -count=1 -v 2>&1 | tee .build/audit/remote-input-go.txt
./scripts/test-input.sh 2>&1 | tee .build/audit/remote-input-native.txt
./scripts/test-connection.sh 2>&1 | tee .build/audit/remote-input-connection.txt
```

Evidence logs: [remote-input-go.txt](../.build/audit/remote-input-go.txt), [remote-input-native.txt](../.build/audit/remote-input-native.txt), and [remote-input-connection.txt](../.build/audit/remote-input-connection.txt). These are local `.build` artifacts and are not committed source files.

The Go package passed in 1.658 seconds with the race detector. Individual executed cases were QUIC mutual authentication/reconnect, OSC working directory/foreground metadata, blocked input without workspace blockage, query replies during paste, and foreground Ctrl+C. The native script passed the keyboard/PTY, Kitty/IME/focus and Metal-child attachment checks. Connection tests passed 32 MiB ordered delivery, barriers/EOF, coalescing, bounded backpressure, cancellation/wakeups, framing, a real server-first socket greeting, and helper-to-socket bootstrap with exactly-once early-request fallback. The measured small greeting/reply took 7 ms in that run; this is a fixture latency, not an application launch benchmark.

The Mac was locked during this verification pass. The AppKit harness creates its own NSWindow and dispatches synthetic events; it does not demonstrate a user's first physical key in a freshly launched, unlocked application. These results also do not cover external SSH, blocked-UDP fallback, Linux login accounting, Tailscale registration, or real remote clipboard transfer. No native remote GUI acceptance check was performed while locked.

## Remaining acceptance work

1. Use a disposable Linux host with an installed matching service and known SSH key. Add it through the native form, create/rename/split remote sessions, open the remote directory picker, and verify process identity and state after quitting/reopening the GUI.
2. Repeat with UDP blocked so SSH fallback is required. Confirm one command execution, no duplicate input, and the same process after interruption/reconnect. Exercise a genuinely offline host and then restore connectivity.
3. Demonstrate `who`, `loginctl`, shell initialization and per-user limits for each terminal only after a real login/session implementation exists. Test actor authorization explicitly; running the existing daemon as root is not equivalent.
4. Test remote plain-text copy, paste, bracketed paste, and application clipboard writes in focused/unfocused panes. Define which clipboard directions/formats are actually supported before claiming parity.
5. Run the two-window/two-host picker scenario and ordinary local CLI operations targeting a remote. The latter needs an implementation beyond the current raw `remote` bridge.
6. Implement and test service-specific Tailscale registration/discovery, focus reporting, omitted mouse events and physical keys where the target behavior requires them. Do not infer undocumented Superlogical settings or protocol compatibility from shared Ghostty components.
