# Interface questions and developer replies

Read on 20 September 2026 in the user's logged-in Chrome session, using read-only Computer Use. No posts, reactions, follows, messages, or account settings were changed. Scope: the eight interface-related threads below. This supplements the video/transcript corpus and does not replace it.

Two concrete requirements emerged that were not explicit in the original inventory: **respect macOS Reduce Motion by disabling animations (A11)** and **independent search in multiple split panes (A12)**. Search replies also clarify that avoidance follows the active match, not every occurrence. Several attractive suggestions were only requests or future ideas; they must not be treated as shipped functionality.

## Confirmed behavior and useful clarification

| Topic | Parent question or context | Developer answer and interpretation |

| **A11: Reduce Motion** | A reader objects to repeated animated transitions in the [peek discussion](https://x.com/mynatsockacct/status/2087618076736987308). | Mitchell says [the macOS setting to limit animation is respected and animation is disabled](https://x.com/mitchellh/status/2087621503219323240). The earlier implementation audit found unconditional `withAnimation` calls; a system-setting check is required for parity. |

## Implications for the parity audit

1. Add and verify A11 and A12. Neither was covered by merely matching the visible preview layout.
2. Tighten A05 around actual active-match rectangles, roughly one-row vertical avoidance, and each pane's own search. A single global search model is insufficient.
3. Keep N07/N08 marked partial until previews are verified while content changes, through both gesture and non-gesture entry points, with reduced motion enabled.
4. Preserve uncertainty about unpublished key bindings, simultaneous dual tab bars, theme values, exact image/shaping support, and platform-specific plans.
5. Keep explicit roadmap ideas and unanswered requests in a separate backlog. They should not inflate the confirmed-feature count or be represented as features Superlogical already has.

No runtime implementation was changed as part of this reply research.
